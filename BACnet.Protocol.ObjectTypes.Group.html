    BACnet.Protocol.ObjectTypes.Group (bacstack v0.1.0-dev.2)

    View Source

    A Group gathers properties from local objects so a client can read them together. For example, a room's Group could expose the temperature, setpoint and occupancy from three different objects. A read of present_value returns a value or access error for each selected property.

    list_of_group_members contains BACnet.Protocol.AccessSpecification values. Each names one object and one or more properties, optionally with array indices. present_value contains one BACnet.Protocol.ReadAccessResult per specification, with individual values or access errors in BACnet.Protocol.ReadAccessResult.ReadResult entries.

    Object Description (ASHRAE 135)

    The Group object type defines a standardized object whose properties represent a collection of other objects and one or more of their properties.

    Configuration and membership

    Supply a nonempty list_of_group_members when creating a local instance. There is no implicit empty membership default. Each specification needs a nonempty property list. Membership is writable through lifecycle preparation, although the standard does not require support for writing that property. A member property entry is a read reference - its property_value must be nil. Selectors cannot carry an array index.

    Members reside in the same device as the Group. Access specifications have no device field, and the module passes local references to the host. The host needs to resolve them in that device, without rerouting an unresolved member to a remote device. An unavailable object or property produces an access error when read - configuration does not perform I/O to check whether members are currently accessible.

    A Group may refer to another Group's metadata, but cannot refer to present_value of a Group or Global Group. ALL and REQUIRED selectors on those object types are also rejected because they include that required property. OPTIONAL and explicit metadata references remain permitted. Named and numeric identifiers use the same checks.

    Fresh reads through the lifecycle

    Every read of present_value needs BACnet.Protocol.ObjectExecution.Lifecycle.prepare_read/2 with the matching property-read trigger. It fetches the member properties and reconstructs the entire result. Retain the returned result and obtain its value with get_property/2 before the next operation. An aggregate ALL or REQUIRED read trigger also refreshes the value, because those selections include it. present_value is a BACnet list, so indexed reads are rejected.

    The returned object holds the values for that read. Prepare a new result for each subsequent request, even if the clocks and source values are the same. Initialization and membership writes clear the old result. Group acquires members only for reads that include Present_Value, so it requests no timer and preserves the supplied runtime state.

    The object execution host owns instance storage, operation ordering and property-service access. It needs to retain object/state/request together and supply a bounded read callback in BACnet.Protocol.ObjectExecution.Context. When a member has computed properties, the callback needs to refresh that member through its lifecycle, retain it and finish immediate continuations before returning the requested value. Detect cyclic reads and avoid synchronously calling an owner already blocked executing the Group. Reads are sequential and preserve request order - they do not form an atomic transaction across member objects.

    Read callback values and property selectors

    Ordinary member reads use BACnet.Protocol.ObjectExecution.Context.read_property/2 with a local BACnet.Protocol.DeviceObjectPropertyRef, including the requested array index. The callback returns {:ok, value} with the source property's native representation, or {:error, reason}. Group converts values through BACnet.Protocol.ObjectsUtility.cast_value_to_property/4 and constructs its own BACnet.Protocol.ReadAccessResult.ReadResult entries. NULL, array-length reads, priority slots and virtual identity/property-list values are handled at the conversion boundary.

    BACnet.Protocol.ApplicationTags.Encoding values and lists of encodings can also be returned and are preserved. These are useful for proprietary properties or object types whose datatype the library cannot infer. Empty lists are valid encoded values. A native value that cannot be encoded becomes PROPERTY / INVALID_DATATYPE for that property, and following reads still proceed. There is no lookup callback requirement.

    ALL, REQUIRED and OPTIONAL use the separate BACnet.Protocol.ObjectExecution.Context.read_property_multiple/3 operation. The callback receives a local BACnet.Protocol.DeviceObjectRef and a one-element selector list. It returns {:ok, properties} with a map of property identifiers to native values, analogous to the map returned by BACnet.Stack.ClientHelper.read_property_multiple/5:

    %{object_name: "Source", present_value: 21.5,
  description: {:error, :read_access_denied}}

    For indexed entries, use {property_identifier, array_index} as the key. Put {:error, reason} in the map when an individual property fails. Return {:error, reason} directly when the whole operation fails. Group builds the BACnet result from those values and errors. An empty map adds no entries to the result.

    The host's property-service layer needs to select from the member's actual property catalog:

    • ALL includes all implemented properties, including proprietary ones.
    • REQUIRED includes standard properties with conformance code R or W.
    • OPTIONAL includes present standard properties with conformance code O.
    • Property_List is excluded from ALL and REQUIRED. The module also removes it from those maps if supplied by the callback. It remains readable when requested explicitly.

    The map needs to retain failures of selected properties as error entries. Helpers that discard failed properties need an adapter preserving those errors for Group. In particular, the transformed map from BACnet.Stack.ClientHelper.read_property_multiple/5 omits property access errors - its return shape is the model for this API, while a faithful Group read also needs those error entries.

    Group cannot infer a complete service catalog from a struct's fields alone - a host may expose virtual, proprietary and conditionally present properties. The callback supplies the property I/O results; Group owns member traversal, value conversion and result construction. Explicit member/property order and duplicates are preserved. Since maps have no request order, selector expansions use ascending numeric property identifier, followed by array index. A map must not introduce a forbidden nested Group value or an unexpanded selector.

    Errors, writes and restart

    Operational failures produce per-property BACnet errors in a successful lifecycle result. Following properties and members are still attempted, even if every acquisition fails. BACnet.Protocol.BACnetError values are preserved, including proprietary class/code values. The following library errors have convenience mappings:

    Callback reasonError class/code
    :unknown_objectOBJECT / UNKNOWN_OBJECT
    :unknown_property, :unknown_property_identifierPROPERTY / UNKNOWN_PROPERTY
    :read_access_denied, :invalid_array_index, :property_is_not_an_array, :invalid_datatype, :value_out_of_rangePROPERTY / corresponding code
    Other reasons, including timeouts and cyclic executionDEVICE / OPERATIONAL_PROBLEM

    The known object/property errors also accept the library's {reason, detail} form. A host that needs a more specific mapping should return a BACnet.Protocol.BACnetError directly. Exceptions, malformed callback results and invalid selector expansions remain programming errors. Configuration errors and missing required callbacks are rejected before acquisition. The Group object has no Reliability property or intrinsic reporting implementation.

    Client writes to present_value are denied. For membership changes, build a candidate through update_property/3, prepare it with BACnet.Protocol.ObjectExecution.Lifecycle.prepare_write/3, commit the returned candidate and execute the same write trigger. Preparation clears the old value without acquiring replacements. Low-level property updates alone do not run the lifecycle.

    After restart, initialize with fresh clocks and state, then refresh before reading the value. A remote Group snapshot stays passive, preserves its supplied state and rejects local write preparation. Remote snapshots do not acquire the remote device's member properties.

    Examples

    Create a Group and read a single member through the lifecycle:

    iex> alias BACnet.Protocol.AccessSpecification
iex> alias BACnet.Protocol.AccessSpecification.Property
iex> alias BACnet.Protocol.ObjectExecution.{Context, Lifecycle}
iex> alias BACnet.Protocol.ObjectIdentifier
iex> alias BACnet.Protocol.ObjectTypes.Group
iex> member = %AccessSpecification{
...>   object_identifier: %ObjectIdentifier{type: :analog_value, instance: 2},
...>   properties: [%Property{property_identifier: :present_value,
...>     property_array_index: nil, property_value: nil}]}
iex> {:ok, group} = Group.create(1600, "ZoneGroup", %{list_of_group_members: [member]})
iex> context = Context.new({:property_read, :present_value, nil},
...>   now: ~U[2026-11-09 08:00:00Z], monotonic_time: 0,
...>   read_property: fn _reference -> {:ok, 21.5} end)
iex> {:ok, stored} = Lifecycle.prepare_read(group, context)
iex> [member_result] = stored.object.present_value
iex> [property_result] = member_result.results
iex> {stored.object.object_name, property_result.property_value.value, stored.next_execution}
{"ZoneGroup", 21.5, nil}

    Retain stored before serving the result. Each subsequent present-value read needs another lifecycle read even when its clocks are unchanged. A complete walkthrough of fresh reads, selectors, partial failures and membership writes is available at examples/objects_lifecycle/group_lifecycle.exs in the repository.

    common_object_opts()

    @type common_object_opts() ::
  {:allow_numeric_constants, boolean()}
  | {:allow_unknown_properties, boolean()}
  | {:ignore_unknown_properties, boolean()}
  | {:revision,
     BACnet.Protocol.Constants.protocol_revision() | non_neg_integer()}
  | {:skip_property_validation_remote_object, boolean() | :value}

    Common object options for creation - all are optional.

    • allow_numeric_constants - Constants are atoms and thus unknown constants or vendor extensions are integers and thus are rejected. Enabling this option will allow integers (non_neg_integer()) for properties with a Constants.type() spec.
    • allow_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties (numeric identifiers usually means we dont know them) are accepted and put into a separate map. This does mean we can not validate or write them. Types of the values can be anything at this point. While you can read unknown properties with atom or integer as property identifier, you can only remove numeric unknown property identifiers from an object. Property identifiers of type atom are only accepted, if it is a remote object (object implementation is only enforced if it is a local object). Numeric property identifiers are accepted regardless of remote object or not. For remote objects, this means you have to write "raw values" (usually BACnet.Protocol.ApplicationTags.Encoding structs).
    • ignore_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties get ignored, as if they were not specified.
    • revision - The BACnet protocol revision used for required properties and annotation conditions. Accepts a non-negative protocol revision number (for example, 19) or a name from BACnet.Protocol.Constants.protocol_revision/0. Optional properties remain available unless an annotation prohibits them. Default required annotations use ASHRAE 135-2012 (revision 14), or the addendum/revision that introduced a later object type.
    • skip_property_validation_remote_object - Skips property validation for remote objects. Sometimes it is possible that the value is invalid as per BACnet specification (i.e. value 0 for a multistate object), but you still want those to be represented. Value true neither type nor value are validated. Value :value means the type is still validated and only the value validator is not run (if present). The property's validator_fun will also be skipped.
