    BACnet.Protocol.ValueSource (bacstack v0.1.0-dev.2)

    View Source

    The Value Source identifies the source of a value.

    In building control systems, an object may be manipulated by a number of entities, and it may be important to know which entity is the current source of the current value. The priority at which an object is commanded indicates the general process that is controlling it (scheduling, manual override, etc.), the value source mechanism allows for an object to indicate the device, and/or object that was the source of the command or write operation.

    The type field selects one of three alternatives:

    • :none: no source is specified.
    • :object: the object field contains a BACnet.Protocol.DeviceObjectRef. Its optional device identifier qualifies a remote object; without it the object is local.
    • :address: the address field contains a BACnet.Protocol.RecipientAddress. Network number 0 denotes the local network.

    The nested structures reuse the existing reference and address types. All fields must be supplied when constructing a source; unused fields should be nil. Encoding and validation use the field selected by type. Parsing sets unused fields to nil.

    Value source mechanism (Clause 19.5)

    value_source identifies the origin of the current present_value (or mode for Life Safety objects). For commandable properties, it follows the entry in value_source_array at the priority supplying the current value. If all priorities are relinquished and relinquish_default supplies the value, the source is none. For non-commandable properties, it records the last writer; there is no value_source_array.

    A write or command normally records the originating device's Device object when its instance is known, or its network address otherwise. A local object initiating the operation is identified directly. Thus an object source can reference either a Device object or the specific object initiating a command.

    The originating device may subsequently refine the source information by writing value_source, using the same priority for a commandable property. Such a refinement does not update last_command_time. Subscriptions to value_source also report source changes according to Clause 19.5.2. This module represents the datatype; priority selection, write authorization, and COV reporting are responsibilities of the objects using it.

    ASN.1 (ASHRAE 135-2016)

    BACnetValueSource ::= CHOICE {
  none     [0] NULL,
  object   [1] BACnetDeviceObjectReference,
  address  [2] BACnetAddress
}

    Alternative 0 uses a primitive context tag with an empty payload. Alternatives 1 and 2 use constructed context tags containing the respective SEQUENCE. The address SEQUENCE contains an application-tagged Unsigned16 network number followed by an application-tagged OCTET STRING MAC address.

    Examples

    iex> alias BACnet.Protocol.ValueSource
iex> source = %ValueSource{type: :none, object: nil, address: nil}
iex> ValueSource.encode(source)
{:ok, [tagged: {0, <<>>, 0}]}
iex> ValueSource.parse([{:tagged, {0, <<>>, 0}}, {:unsigned_integer, 7}])
{:ok, {%ValueSource{type: :none, object: nil, address: nil}, [unsigned_integer: 7]}}

iex> alias BACnet.Protocol.{DeviceObjectRef, ObjectIdentifier, ValueSource}
iex> source = %ValueSource{type: :object, address: nil, object: %DeviceObjectRef{
...>   device_identifier: nil,
...>   object_identifier: %ObjectIdentifier{type: :analog_input, instance: 24}
...> }}
iex> ValueSource.encode(source)
{:ok, [constructed: {1, [tagged: {1, <<0, 0, 0, 24>>, 4}], 0}]}

iex> alias BACnet.Protocol.{RecipientAddress, ValueSource}
iex> source = %ValueSource{type: :address, object: nil,
...>   address: %RecipientAddress{network: 0, address: :broadcast}}
iex> ValueSource.encode(source)
{:ok, [constructed: {2, [unsigned_integer: 0, octet_string: <<>>], 0}]}

    valid?(t)

    @spec valid?(t()) :: boolean()

    Returns whether the selected source is well-formed.

    Object references are validated by BACnet.Protocol.DeviceObjectRef.valid?/1. Addresses require an integer network number in 0..65_535 and a binary MAC address or :broadcast. MAC length and format depend on the data link and are not restricted here. The :none alternative is always valid. Unused fields do not affect validation.
