    BACnet.Protocol.ObjectTypes.AnalogOutput (bacstack v0.1.0-dev.2)

    View Source

    An Analog Output holds the command for an actuator such as a valve, damper or variable-speed drive. Its present_value is the highest-priority active command. When all 16 slots in the priority_array are empty, it uses relinquish_default.

    The object carries a COV threshold (cov_increment) and can be placed out of service. intrinsic_reporting: true selects OUT_OF_RANGE reporting properties, including high_limit, low_limit and deadband. Core lifecycle execution maintains the command and supplied reliability - event detection and notification delivery remain separate. Typical companion properties are units, min_present_value, max_present_value, resolution and device_type.

    Object Description (ASHRAE 135)

    The Analog Output object type defines a standardized object whose properties represent the externally visible characteristics of an analog output.

    Analog Output objects that support intrinsic reporting shall apply the OUT_OF_RANGE event algorithm.

    Behaviour and Operation

    Analog Output is always commandable. Its required priority_array and relinquish_default determine the effective present_value in engineering units. The lowest numbered non-nil priority slot wins. Lower-priority commands remain stored while masked. A nil command relinquishes only its slot, revealing the next command or the relinquish default when all slots are nil. Both BACnet commands and local software commands follow this mechanism, including while out of service.

    Use set_priority/3 to construct a Present_Value write candidate. A BACnet write without an explicit priority means 16 - the host needs to supply that default to the setter. The array is read-only to BACnet clients. Internal configuration can use the property operations to update the array or relinquish default. Direct Present_Value updates must not bypass arbitration, including during simulation. Existing property operations keep Present_Value synchronized after priority/default changes.

    Priority 6 is reserved for minimum on/off control and is unavailable for commands or relinquishment through set_priority/3. Analog Output has no minimum on/off timing. Lifecycle preflight rejects a stored non-nil slot 6 with {:error, {:invalid_configuration, :priority_6}}.

    Lifecycle and host contract

    The object execution host is the integrating application or higher-level BACnet stack that retains objects and runtime state, serializes operations and supplies their context. The host's physical adapter applies commands to the output channel and reports hardware reliability. This module starts no process and invokes no hardware or host I/O callback.

    Initialize with BACnet.Protocol.ObjectExecution.Lifecycle.execute/2 and an :initialization context. Retain the full returned result. For every write, construct a candidate through this module's property operations, call BACnet.Protocol.ObjectExecution.Lifecycle.prepare_write/3, commit the prepared object and execute with the same context and previous runtime state before exposing another operation. Only then may the host pass the retained command to an in-service adapter. Raw property setters do not run lifecycle origin checks or execution. Deliver every accepted write, including same-value writes.

    The host still needs to enforce service permissions, read-only annotations, array indices and BACnet priority rules. Preparation is pure. A rejected write leaves the original object, runtime state and wakeup unchanged. Missing, malformed or other-instance state returns {:error, :invalid_execution_state}. Initialize local instances before other operations. Initialization seeds state from supplied properties - it performs no hardware write or status acquisition.

    Physical output and out-of-service simulation

    While in service, the host needs to apply the retained effective command through its driver. get_output/2 selects that command without performing I/O or measuring the actuator. Scaling, calibration, hardware limits and the driver implementation are local matters. The device_type property can describe the attached channel or actuator. Commanded output does not establish that the physical output reached that value.

    While out_of_service is true, Present_Value changes are decoupled from the physical output. The host needs to implement that isolation. Its physical policy may hold the last output, select a configured fallback or follow other local logic. get_output/2 returns its caller-supplied fallback while out of service - the default is 0.0. That fallback is an API default, not a measured output or a prescribed physical policy. Returning to service requires the host to apply the current retained command, including commands accepted during simulation.

    Logical commands from both origins continue to arbitrate while out of service. Use {:property_write, property, array_index, priority} for BACnet requests and {:application_write, property, array_index, priority} for local application updates. A local adapter handling a BACnet request needs to preserve the BACnet origin. In-service hardware Reliability reports can use application-write triggers with :reliability. Explicit Reliability writes from either origin can simulate conditions while out of service, including same-value writes. The host needs to stop forwarding automatic hardware Reliability reports while decoupled - write origin alone does not distinguish an automatic report from intentional simulation.

    Reliability, inhibition and status flags

    The host supplies physical reliability, such as :no_output or :communication_failure, from its adapter's diagnosis. The lifecycle does not infer hardware failure from a rejected write, a range error or an invalid runtime state. No feedback value is copied from a command. Physical observations belong to the host - later Interface_Value, Current_Command_Priority and value-source properties remain outside this module's current declared property set.

    In-service Reliability reports are retained separately from out-of-service simulation. When returning to service, a retained physical report replaces simulated Reliability. If initialization began out of service and no physical report is known, the supplied property remains until a fresh report arrives. The host needs to supply fresh status when retained observations are insufficient for its application.

    When selected, reliability_evaluation_inhibit presents NO_FAULT_DETECTED while true, except for an explicitly supplied or written Reliability while out of service. Entering out of service alone does not expose a previously suppressed hardware report. Returning to service while inhibited masks simulation again. The latest retained physical report becomes effective when inhibition ends. Hardware reports received while inhibited and in service are retained for that later evaluation.

    Existing property propagation maintains FAULT from Reliability, IN_ALARM from the supplied Event_State and OUT_OF_SERVICE from Out_Of_Service. Removing Reliability clears FAULT during execution. OVERRIDDEN remains a local indication for the host to supply when applicable.

    Reads, timing and restart

    Before a read, use BACnet.Protocol.ObjectExecution.Lifecycle.prepare_read/2, retain its result and obtain the property through get_property/2. An active reporting delay can request a monotonic wakeup. The host replaces its previous request when retaining each result.

    After a restart, initialize from restored object properties with fresh context and runtime state. In-service supplied Reliability seeds the physical report. An initially out-of-service supplied Reliability seeds simulation instead. A suppressed physical report held only in old runtime state cannot be recovered from NO_FAULT_DETECTED - supply a fresh adapter report when needed. Remote snapshots remain passive, preserving their object and context state without callbacks or wakeups. Local write preparation for a remote snapshot returns {:error, :operation_not_available_for_remote_objects}.

    Configuration, intrinsic reporting and COV

    units, min_present_value, max_present_value and resolution describe the engineering value and usable range. When both min/max properties are present, the existing range validator applies to priority commands and relinquish defaults. The lifecycle introduces no rounding, unit conversion or automatic clamping.

    With intrinsic_reporting: true, execution evaluates OUT_OF_RANGE using the effective command and enabled limits. Reliability faults take precedence. Event and recovery delays use monotonic time. The host retrieves transitions with BACnet.Protocol.ObjectExecution.EventReporting.transition/1 after retaining the result. cov_increment represents the COV threshold for the host's subscriptions and delivery.

    Complete command example

    This example supplies a command and retains the result before selecting the value for a physical adapter. The final getter performs no hardware operation.

    iex> alias BACnet.Protocol.ObjectExecution.{Context, Lifecycle}
iex> {:ok, object} = BACnet.Protocol.ObjectTypes.AnalogOutput.create(40, "Valve command", %{units: :percent, relinquish_default: 20.0})
iex> start = Context.new(:initialization, now: ~U[2026-11-08 10:00:00Z], monotonic_time: 0)
iex> {:ok, stored} = Lifecycle.execute(object, start)
iex> write = Context.new({:property_write, :present_value, nil, 8}, now: ~U[2026-11-08 10:00:01Z], monotonic_time: 1000, state: stored.state)
iex> {:ok, candidate} = BACnet.Protocol.ObjectTypes.AnalogOutput.set_priority(stored.object, 8, 45.0)
iex> {:ok, prepared} = Lifecycle.prepare_write(stored.object, candidate, write)
iex> stored = %{stored | object: prepared}
iex> {:ok, stored} = Lifecycle.execute(stored.object, write)
iex> {BACnet.Protocol.ObjectTypes.AnalogOutput.get_output(stored.object), stored.next_execution}
{45.0, nil}

    A runnable simulated-adapter walkthrough is examples/objects_lifecycle/analog_output_lifecycle.exs.

    Common object options for creation - all are optional.

    • allow_numeric_constants - Constants are atoms and thus unknown constants or vendor extensions are integers and thus are rejected. Enabling this option will allow integers (non_neg_integer()) for properties with a Constants.type() spec.
    • allow_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties (numeric identifiers usually means we dont know them) are accepted and put into a separate map. This does mean we can not validate or write them. Types of the values can be anything at this point. While you can read unknown properties with atom or integer as property identifier, you can only remove numeric unknown property identifiers from an object. Property identifiers of type atom are only accepted, if it is a remote object (object implementation is only enforced if it is a local object). Numeric property identifiers are accepted regardless of remote object or not. For remote objects, this means you have to write "raw values" (usually BACnet.Protocol.ApplicationTags.Encoding structs).
    • ignore_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties get ignored, as if they were not specified.
    • revision - The BACnet protocol revision used for required properties and annotation conditions. Accepts a non-negative protocol revision number (for example, 19) or a name from BACnet.Protocol.Constants.protocol_revision/0. Optional properties remain available unless an annotation prohibits them. Default required annotations use ASHRAE 135-2012 (revision 14), or the addendum/revision that introduced a later object type.
    • skip_property_validation_remote_object - Skips property validation for remote objects. Sometimes it is possible that the value is invalid as per BACnet specification (i.e. value 0 for a multistate object), but you still want those to be represented. Value true neither type nor value are validated. Value :value means the type is still validated and only the value validator is not run (if present). The property's validator_fun will also be skipped.

    Represents an Analog Output object. Treat struct fields as read-only. Use the object module's property functions to build updates.

    Create the object with intrinsic_reporting: true to select its intrinsic reporting properties. The fields for those properties are nil when omitted.

    For a commandable instance, use set_priority/3 to change the effective Present_Value.

    get_output/2 selects the command or a caller-supplied out-of-service fallback. It does not acquire physical state or perform hardware I/O.
