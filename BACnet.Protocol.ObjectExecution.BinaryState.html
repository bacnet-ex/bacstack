    BACnet.Protocol.ObjectExecution.BinaryState (bacstack v0.1.0-dev.2)

    View Source

    Shared logical history for binary objects and minimum times for commandable/value objects. Tracks logical transitions, elapsed active time and minimum on/off holds for binary objects.

    BACnet.Protocol.ObjectTypes.BinaryInput, BACnet.Protocol.ObjectTypes.BinaryValue and BACnet.Protocol.ObjectTypes.BinaryOutput call these helpers after applying their own write and capability checks. Use BACnet.Protocol.ObjectExecution.Lifecycle to drive those objects from an application.

    Preparation and execution

    prepare_write/3 is pure. It reconciles the candidate's priority-6 hold and stamps reset times on explicit zero writes. It changes neither retained runtime state nor host storage. execute/3 advances history and returns a replacement result. The object module supplies its own property contract, and property updates use the actual object's API. Callers must retain that result before another operation observes the object.

    Minimum durations and active seconds use supplied monotonic milliseconds. Transition and reset timestamps use device-local wall time. Active-time accounting uses logical Present_Value for all three object types, with fractional milliseconds retained across inactive periods. Binary Value's state-change count wraps modulo 2^32. Binary Input and Binary Output use a non-negative count with no fixed wrap limit. Elapsed seconds wrap modulo 2^32 for all three types. Counter wrap is not an explicit reset.

    Initialization establishes a baseline, retaining historical totals. A stored priority-6 hold restarts its full applicable duration at the new monotonic origin. Obsolete holds are reconciled, and actual changes of Present_Value are recorded. Non-commandable Binary Value rejects conflicting writes until its hold expires instead of creating an array. Binary Output is always commandable. Binary Input has neither priorities nor minimum durations.

    Hardware state, feedback, polarity and physical reliability are outside these calculations. Those responsibilities are documented by BACnet.Protocol.ObjectTypes.BinaryOutput. The shared runtime state remains opaque to the host and is isolated by object type and identifier. It cannot be reused across VM restarts.

    state()

    @type state() :: %{
  kind: :binary_input | :binary_value | :binary_output,
  identifier: BACnet.Protocol.ObjectIdentifier.t(),
  value: boolean(),
  observed_at: integer(),
  transitioned_at: integer() | nil,
  count: non_neg_integer() | nil,
  active_seconds: BACnet.Protocol.ApplicationTags.unsigned32() | nil,
  active_remainder: 0..999
}

    Runtime state for one binary object instance. Pass it back on the next execution.

    value is the last effective logical state. observed_at and transitioned_at use VM-monotonic milliseconds. Totals mirror the selected property groups, or are nil when absent. active_remainder retains the unpublished fraction of an active second.

    Updates logical history and accounts for elapsed time after the object module checks the operation.

    Supply the object's contract, property hooks, fresh clocks and its previous state. The result's wakeup replaces the previous request. This function performs no hardware or host I/O.

    prepare_write(candidate, context, contract, hooks)

    @spec prepare_write(
  binary_object(),

  BACnet.Protocol.ObjectsContract.t(),
  BACnet.Protocol.ObjectOperations.operation_hooks()
) :: {:ok, binary_object()} | {:error, term()}

    Prepares priority holds and explicit reset timestamps on a validated write candidate.

    The object module must first validate configuration, runtime state and write origin. Supply that module's contract and property hooks. No I/O or runtime-state update occurs here.
