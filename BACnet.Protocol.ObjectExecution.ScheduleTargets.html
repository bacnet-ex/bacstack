    BACnet.Protocol.ObjectExecution.ScheduleTargets (bacstack v0.1.0-dev.2)

    View Source

    Internal reference validation and target planning for Schedule execution.

    BACnet.Protocol.ObjectTypes.Schedule uses this module to prepare an ordered list of target writes. Applications driving objects should use BACnet.Protocol.ObjectExecution.Lifecycle. Schedule uses these helpers to validate references and prepare writes before issuing commands.

    Planning and execution phases

    validate_references/2 checks reference representation without host I/O. required_operations/2 determines which callbacks the selected references require, also without invoking them. Both support the Schedule's execution preflight.

    prepare/5 is an execution-time operation. It may invoke BACnet.Protocol.ObjectExecution.Context.lookup_object/2 to inspect local targets, cast values through BACnet.Protocol.ObjectsUtility.cast_property_to_value/4, and validate hypothetical property or priority updates. It does not commit those candidates or invoke BACnet.Protocol.ObjectExecution.Context.write_property/4. Each result is a plan/0.

    This planning step is separate from BACnet.Protocol.ObjectExecution.Lifecycle.prepare_write/3, which validates a proposed write to the Schedule itself without host I/O. During Schedule execution, the object module publishes its computed value and plans in an immediate result. After the host retains the result, the continuation sends the commands through the host's write callback.

    References, values and failures

    A reference without a device identifier is local. An explicit identifier equal to the context's local device_identifier is normalized to nil. Other qualified references remain remote - without a local identity, every device-qualified reference is forwarded as remote.

    Local target plans check object identity, property access, array indices and compatibility of the selected value and configured output values. Casting uses the identifier from the target module's object-identifier getter and the existing object-type mapping. NULL command relinquishment and array length handling stay in the local planning/write paths. Array elements use the caster's allow_partial: true option. The host still needs to enforce service permissions, reserved-priority rules and property-specific resizing when applying a write.

    Remote targets require no lookup or local object model. Their plans preserve the original encoding and qualified reference. The write callback needs to resolve the device's destination and report the remote service result. Property array indices and the supplied command priority need to be preserved when forwarding to BACnet.Stack.ClientHelper.write_property/6.

    Plans retain target order, including failed plans. Schedule decides how those errors affect its Reliability property and continues with other valid targets. Host callback exceptions and malformed lookup results are programming errors and may raise rather than become failed plans.

    Example

    This example plans one local, one explicit self-device and one remote write. Its write callback raises if called, demonstrating that planning does not perform the writes.

    iex> alias BACnet.Protocol.ApplicationTags.Encoding

iex> alias BACnet.Protocol.ObjectExecution.{Context, ScheduleTargets}

iex> identifier = BinaryOutput.get_object_identifier(target)

iex> remote_device = %ObjectIdentifier{type: :device, instance: 43}
iex> reference = %DeviceObjectPropertyRef{device_identifier: nil,
...>   object_identifier: identifier, property_identifier: :present_value, property_array_index: nil}

...>   %{reference | device_identifier: remote_device}]

...>   monotonic_time: 0, device_identifier: device,
...>   lookup_object: fn %DeviceObjectRef{object_identifier: ^identifier, device_identifier: nil} ->
...>     {:ok, target}
...>   end,

...>   ScheduleTargets.prepare(references, on, [null, on], 8, context)

    plan()

    @type plan() ::
  {BACnet.Protocol.DeviceObjectPropertyRef.t(),
   preparation_result ::
     {:ok, BACnet.Protocol.ApplicationTags.Encoding.t()} | {:error, term()}}

    One normalized target reference paired with the selected encoding or a preparation error.

    Success retains the original selected BACnet.Protocol.ApplicationTags.Encoding, including NULL - the value is not replaced by its local Elixir representation. Local casting is used only for compatibility checks. A failed plan contains the lookup, access, index, casting or candidate-validation error. An explicit self-device identifier is normalized to nil in either case. Remote references retain their device identifier.

    A successful remote plan means it is ready to pass to the host callback - remote property compatibility has not been inspected. The priority passed to prepare/5 is used for local validation but is not stored in this tuple. Schedule retains its command priority separately.

    Functions

    prepare(references, value, configured_values, priority, context)

    @spec prepare(
  [BACnet.Protocol.DeviceObjectPropertyRef.t()],
  BACnet.Protocol.ApplicationTags.Encoding.t(),
  [BACnet.Protocol.ApplicationTags.Encoding.t()],
  1..16,
  BACnet.Protocol.ObjectExecution.Context.t()
) :: [plan()]

    Builds ordered target plans without performing target writes.

    References must have passed validate_references/2. The selected value and configured_values must be valid primitive encodings, and priority must be in 1..16. For automatic execution, the configured output values come from BACnet.Protocol.ObjectExecution.ScheduleEvaluator.target_values/1. Out-of-service manual execution supplies only the selected value. The selected value is always checked, even if absent from the configured list. Duplicate tag/payload pairs are checked once per local target.

    For each local reference, invokes the context's lookup callback with a local BACnet.Protocol.DeviceObjectRef. It then checks identity, locality, access, index and all supplied output values against the resolved target. Primitive casts use BACnet.Protocol.ObjectsUtility.cast_property_to_value/4 with the target's object identifier. Candidate property/priority operations validate the native values without committing them. NULL relinquishment bypasses ordinary casting for commandable present_value writes. Array elements use partial casting - index zero validates a variable array's Unsigned length, while actual resizing/default initialization remains the host's responsibility.

    Returns one plan/0 per input reference, preserving order and duplicates. Local operational errors become failed plans and do not stop planning later targets. Remote plans retain the selected encoding without lookup or conversion - remote service errors occur during the later write callback. This function invokes no write callback and makes no Reliability update.

    Invalid references violate the precondition and can raise MatchError. Malformed lookup objects raise ArgumentError, while host callback exceptions propagate. See the module example for local, explicit self-device and remote plans with NULL relinquishment among the checked values.

    required_operations(references, context)

    @spec required_operations(
  [BACnet.Protocol.DeviceObjectPropertyRef.t()],
  BACnet.Protocol.ObjectExecution.Context.t()
) :: [atom()]

    Lists the host operations needed by validated target references.

    Call validate_references/2 first. Returns [] for no targets, [:write_property] for remote-only targets, or [:lookup_object, :write_property] if any normalized target is local. Explicit self-device references count as local when the context supplies the matching device identifier. The function neither checks callback availability nor invokes callbacks - availability can be checked through BACnet.Protocol.ObjectExecution.Context.require_operations/2.

    Invalid references violate the precondition and can raise MatchError.

    Example

    iex> alias BACnet.Protocol.{DeviceObjectPropertyRef, ObjectIdentifier}
iex> alias BACnet.Protocol.ObjectExecution.{Context, ScheduleTargets}
iex> reference = %DeviceObjectPropertyRef{
...>   device_identifier: %ObjectIdentifier{type: :device, instance: 42},
...>   object_identifier: %ObjectIdentifier{type: :binary_output, instance: 700},

iex> context = Context.new(:initialization, now: ~U[2026-11-09 08:00:00Z], monotonic_time: 0)

    validate_references(references, context)

    @spec validate_references(term(), BACnet.Protocol.ObjectExecution.Context.t()) ::
  :ok | {:error, term()}

    Checks the representation of a Schedule target-reference list without host I/O.

    Each entry must be a valid BACnet.Protocol.DeviceObjectPropertyRef. Local, explicit self-device and remote references are accepted. The context supplies the local identity used for routing, but no callback is invoked and the input list is not modified.

    Returns :ok for a valid list, including an empty one. Invalid entries or a non-list input return {:error, {:invalid_configuration, :list_of_object_property_references}}. This does not check object existence, property access, target datatypes or callback availability.

    Example

    iex> alias BACnet.Protocol.ObjectExecution.{Context, ScheduleTargets}
iex> context = Context.new(:initialization, now: ~U[2026-11-09 08:00:00Z], monotonic_time: 0)
iex> ScheduleTargets.validate_references([], context)
:ok
iex> ScheduleTargets.validate_references([:invalid], context)
{:error, {:invalid_configuration, :list_of_object_property_references}}
