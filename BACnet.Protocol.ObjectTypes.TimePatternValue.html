    BACnet.Protocol.ObjectTypes.TimePatternValue (bacstack v0.1.0-dev.2)

    View Source

    A Time Pattern Value stores a BACnet time pattern, such as the half-hour mark of every hour. Use BACnet.Protocol.ObjectTypes.TimeValue when the value represents a single time of day.

    Object Description (ASHRAE 135)

    The Time Pattern Value object type defines a standardized object whose properties represent the externally visible characteristics of a named data value in a BACnet device.

    Time Pattern objects can be used to represent multiple recurring times based on rules defined by the pattern of individual fields of the time.

    Values and commandability

    Write a BACnet.Protocol.BACnetTime with update_property/3 on a non-commandable instance. To make an instance commandable, select Priority_Array or Relinquish_Default. The object adds the corresponding partner property. Use set_priority/3 to write a command. The lowest numbered active slot supplies Present_Value, and Relinquish_Default supplies it when all slots are empty.

    Use :unspecified in any hour, minute, second or hundredth field. Direct writes, priority slots and Relinquish_Default preserve those fields. A fully unspecified time can occupy a priority slot. Pass nil to relinquish a slot in response to BACnet NULL. The host needs to use priority 16 when a BACnet command omits its priority. Priority 6 is reserved for minimum on/off control.

    Consumers can interpret the stored pattern for their own purposes. This object keeps the pattern as supplied and does not evaluate it against the device clock or request a wakeup at a matching time.

    Out of service and write origin

    Use :application_write for normal local software and :property_write for BACnet writes. While Out_Of_Service is true, lifecycle preparation rejects application Present_Value writes, including repeated values and masked commands. It also rejects indirect application edits that would change the effective value. BACnet writes remain available for simulation and command prioritization continues. An absent Out_Of_Service property is treated as in service.

    Lifecycle and host contract

    The object execution host needs to own instances, serialize operations and retain runtime state. Initialize with BACnet.Protocol.ObjectExecution.Lifecycle.execute/2 and an :initialization context. Build a candidate through the property operations, call BACnet.Protocol.ObjectExecution.Lifecycle.prepare_write/3, and execute the prepared object with the same context and prior state. Retain the whole result on success. The host needs to enforce service permissions and array indices, preserve the write origin, and deliver every accepted write.

    Use BACnet.Protocol.ObjectExecution.Lifecycle.prepare_read/2 before reading through get_property/2. Execution requires no host I/O or wakeup. After a restart, initialize the restored properties with fresh runtime state. Remote snapshots remain passive and reject local write preparation.

    The runnable walkthrough is examples/objects_lifecycle/time_pattern_value_lifecycle.exs.

    Reliability and reporting

    The application supplies Reliability. Reliability_Evaluation_Inhibit exposes NO_FAULT_DETECTED and retains the reported value for restoration. While out of service, either write origin can supply an explicit alternate Reliability, including while inhibited. Refresh any suppressed report held only in runtime state after restart.

    FAULT follows the exposed Reliability, and OUT_OF_SERVICE follows Out_Of_Service. IN_ALARM reflects the supplied Event_State when present. OVERRIDDEN remains a local indication. This module provides the core value lifecycle. Event_State, when present on an object without event reporting, is NORMAL.

    Examples

    Creating a Time Pattern Value:

    iex> {:ok, tpv} = BACnet.Protocol.ObjectTypes.TimePatternValue.create(110, "Daily", %{present_value: %BACnet.Protocol.BACnetTime{hour: :unspecified, minute: :unspecified, second: :unspecified, hundredth: :unspecified}}); tpv.object_name
"Daily"

    common_object_opts()

    @type common_object_opts() ::
  {:allow_numeric_constants, boolean()}
  | {:allow_unknown_properties, boolean()}
  | {:ignore_unknown_properties, boolean()}
  | {:revision,
     BACnet.Protocol.Constants.protocol_revision() | non_neg_integer()}
  | {:skip_property_validation_remote_object, boolean() | :value}

    Common object options for creation - all are optional.

    • allow_numeric_constants - Constants are atoms and thus unknown constants or vendor extensions are integers and thus are rejected. Enabling this option will allow integers (non_neg_integer()) for properties with a Constants.type() spec.
    • allow_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties (numeric identifiers usually means we dont know them) are accepted and put into a separate map. This does mean we can not validate or write them. Types of the values can be anything at this point. While you can read unknown properties with atom or integer as property identifier, you can only remove numeric unknown property identifiers from an object. Property identifiers of type atom are only accepted, if it is a remote object (object implementation is only enforced if it is a local object). Numeric property identifiers are accepted regardless of remote object or not. For remote objects, this means you have to write "raw values" (usually BACnet.Protocol.ApplicationTags.Encoding structs).
    • ignore_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties get ignored, as if they were not specified.
    • revision - The BACnet protocol revision used for required properties and annotation conditions. Accepts a non-negative protocol revision number (for example, 19) or a name from BACnet.Protocol.Constants.protocol_revision/0. Optional properties remain available unless an annotation prohibits them. Default required annotations use ASHRAE 135-2012 (revision 14), or the addendum/revision that introduced a later object type.
    • skip_property_validation_remote_object - Skips property validation for remote objects. Sometimes it is possible that the value is invalid as per BACnet specification (i.e. value 0 for a multistate object), but you still want those to be represented. Value true neither type nor value are validated. Value :value means the type is still validated and only the value validator is not run (if present). The property's validator_fun will also be skipped.
