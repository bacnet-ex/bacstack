    Modules

    BACnet

    BACstack is a low-level Elixir implementation for the ASHRAE standard 135, BACnet - Building Automation and Controller network. This implementation supports ASHRAE 135-xxxx. See below for implemented transport layers (datalink).

    BACnet.BeamTypes

    Contains functions to resolve typespecs and types from BEAM bytecode into a type declaration and functions to validate those types against values.

    BACnet.Protocol

    This module is mostly used for basic decoding of BACnet frames (Protocol Data Units - PDU).

    BACnet.Protocol.APDU

    This module provides decoding of Application Data Units (APDU).

    BACnet.Protocol.APDU.Abort

    Abort APDUs abruptly terminate an ongoing confirmed transaction.

    BACnet.Protocol.APDU.ComplexACK

    Complex ACK APDUs return successful results that contain data.

    BACnet.Protocol.APDU.ConfirmedServiceRequest

    Confirmed Service Request APDUs carry service invocations that require a reply.

    BACnet.Protocol.APDU.Error

    Error APDUs report that a confirmed service request could not be completed.

    BACnet.Protocol.APDU.Reject

    Reject APDUs are sent when a confirmed service request cannot even be interpreted because of a protocol or syntactical error.

    BACnet.Protocol.APDU.SegmentACK

    Segment ACK APDUs are used during segmented data transfer.

    BACnet.Protocol.APDU.SimpleACK

    Simple ACK APDUs are the minimal successful reply to a confirmed service.

    BACnet.Protocol.APDU.UnconfirmedServiceRequest

    Unconfirmed Service Request APDUs carry one-way service invocations.

    BACnet.Protocol.AccessSpecification

    An Access Specification (also called Read Access Specification or Write Access Specification depending on context) describes a set of properties belonging to a single object that should be read or written together.

    BACnet.Protocol.AccessSpecification.Property

    Represents one property entry inside an Access Specification.

    BACnet.Protocol.AccumulatorRecord

    An Accumulator Record captures a single sample from an Accumulator object at a particular point in time.

    BACnet.Protocol.ActionCommand

    An Action Command is one step inside an Action List that belongs to a Command object. When the Command object is activated (by writing to its present value), the device executes the sequence of Action Commands in order.

    BACnet.Protocol.ActionList

    An Action List is an ordered collection of BACnet.Protocol.ActionCommand entries. Each element of a Command object's Action array contains one such list, representing the sequence selected when that array index is written to the Command's present_value.

    BACnet.Protocol.AddressBinding

    An Address Binding is the mapping between a device's Object Identifier (the Device object instance) and the network address at which that device can be reached. It is the fundamental data structure used by the BACnet address resolution mechanisms.

    BACnet.Protocol.AlarmSummary

    An Alarm Summary entry is the data structure returned by the Get Alarm Summary confirmed service. It gives a client a compact, point-in-time list of every object inside a device that is currently in an alarm or fault condition and that the client is permitted to observe.

    BACnet.Protocol.ApplicationTags

    This module provides application tags encoding and decoding as per ASHRAE 135-2012 Clause 20.2 (and the formal ASN.1 definitions in Clause 21), including support for constructed data and context-specific tags.

    BACnet.Protocol.ApplicationTags.Encoding

    Helper types and functions for working with the decoded form of application tags ({:null, nil}, {:unsigned_integer, 42}, {:constructed, {tag, value, len}}, etc.).

    BACnet.Protocol.ApplicationTags.Encoding.Error

    Exception raised for low-level application tag encoding/decoding failures. Usually wrapped by higher-level error types.

    BACnet.Protocol.BACnetArray

    A BACnet Array (BACnetARRAY in the standard) is an ordered, indexed collection of elements of the same datatype. It is one of the most important structured datatypes in BACnet and appears as the type of many standard object properties.

    BACnet.Protocol.BACnetDate

    A BACnet Date is a structured value that can represent either a specific calendar date or a date pattern containing wildcards and special values. It is one of the fundamental data types in BACnet (application tag 10) and is used pervasively for schedules, calendars, trend-log time ranges, and event timestamps.

    BACnet.Protocol.BACnetDateTime

    A BACnet DateTime is a simple SEQUENCE that combines a BACnet.Protocol.BACnetDate and a BACnet.Protocol.BACnetTime. It is the most common concrete timestamp form used throughout the protocol (application tag 12 when appearing as a primitive).

    BACnet.Protocol.BACnetError

    A BACnet Error is the combination of an Error Class and an Error Code that explains why a service request or action could not be fulfilled. It is transmitted inside Error APDUs and also appears inside the result(-) parameter of many confirmed services (Read Property, Write Property, Create Object, etc.).

    BACnet.Protocol.BACnetTime

    A BACnet Time is a structured value (application tag 11) that can represent either a specific time of day or a time pattern with one or more components marked as :unspecified. It is the natural companion to BACnet.Protocol.BACnetDate and appears in the same contexts: schedules, calendars, trend logs, event notifications, and TimeSynchronization services.

    BACnet.Protocol.BACnetTimestamp

    A BACnet Timestamp is a CHOICE type that can represent three different notions of "when something happened". The most common form is a full BACnet Date and Time. For trend logs that produce very high-frequency samples, a simple sequence number is often used instead because it consumes far less space and avoids the cost of maintaining a real-time clock with sub-second precision. The third form (Time only) is used when only the time of day is significant.

    BACnet.Protocol.BACnetURI

    ASHRAE 135 Annex Q.8 defines a BACnet URI scheme, in cases where a URI is needed to refer to data that is accessible using BACnet services.

    BACnet.Protocol.BroadcastDistributionTableEntry

    A Broadcast Distribution Table Entry describes one peer BBMD (BACnet Broadcast Management Device) or peer network that participates in the distribution of BACnet broadcasts across an IP network. The table as a whole defines the mesh of BBMDs that collectively provide broadcast emulation for an entire site and includes entries to local networks the BBMD should broadcast to.

    BACnet.Protocol.BvlcForwardedNPDU

    Represents a Forwarded NPDU BVLC function (BVLC function 0x04) used in BACnet/IP to forward a message from a foreign device or across a BBMD (ASHRAE 135 Annex J).

    BACnet.Protocol.BvlcFunction

    A BVLC Function is the payload of a BACnet Virtual Link Layer (BVLL) message used on BACnet/IP networks (ASHRAE 135 Annex J). Each function code corresponds to a different operation: Register-Foreign-Device, Read-Broadcast-Distribution-Table, Write-Broadcast-Distribution-Table, and several others used for BBMD and Foreign Device management.

    BACnet.Protocol.BvlcResult

    Represents the result of a BVLC operation (BVLC function 0x00, BVLC-Result) in BACnet/IP (ASHRAE 135 Annex J.2.1). The single-byte result code indicates success or the reason for failure.

    BACnet.Protocol.CalendarEntry

    A Calendar Entry is the CHOICE type used by both Calendar objects and Schedule objects to describe "special" days (holidays, maintenance periods, after-hours operation, etc.).

    BACnet.Protocol.Constants

    BACnet Protocol constants.

    BACnet.Protocol.Constants.ConstantError

    Constants exception.

    BACnet.Protocol.CovSubscription

    A COV Subscription records that a particular client (identified by its Process Identifier and Recipient address) has asked to be notified whenever a specific property (or the entire object) changes value beyond a configured increment.

    BACnet.Protocol.DailySchedule

    A Daily Schedule is a list of BACnet.Protocol.TimeValue pairs that define the desired behavior of a scheduled property for one 24-hour period. It is the fundamental building block of both the normal weekly_schedule (7 entries, one per BACnet.Protocol.DaysOfWeek) and the exception_schedule in Schedule objects.

    BACnet.Protocol.DateRange

    A Date Range defines an inclusive period bounded by a start BACnet.Protocol.BACnetDate and an end BACnet.Protocol.BACnetDate. It is one of the three CHOICE alternatives inside BACnet.Protocol.CalendarEntry (alongside a specific BACnet.Protocol.BACnetDate and a BACnet.Protocol.WeekNDay pattern).

    BACnet.Protocol.DaysOfWeek

    DaysOfWeek is a 7-bit bit string (application tag 8) where each bit represents one day of the week. It is one of the most frequently used building blocks for recurring schedules and exception handling in BACnet.

    BACnet.Protocol.Destination

    A Destination describes where and when event notifications should be sent for a particular recipient. It is the core data structure used inside Notification Class objects to define the distribution list for alarms and events.

    BACnet.Protocol.Device.ObjectTypesSupported

    BACnet object types need to be supported by the device, in order for a BACnet client to be able to handle them.

    BACnet.Protocol.Device.ServicesSupported

    BACnet Services need to be supported by the device, in order for a BACnet client to be able to invoke them.

    BACnet.Protocol.DeviceObjectPropertyRef

    A Device Object Property Reference is the most complete form of property reference in BACnet. It identifies a specific property (with optional array index) inside a specific object, optionally qualified by the device that contains that object.

    BACnet.Protocol.DeviceObjectRef

    A DeviceObjectRef points to an object, optionally qualified by the device that contains it. It is one of the most common reference types in the entire BACnet object model.

    BACnet.Protocol.EnrollmentSummary

    An Enrollment Summary entry is produced by the Get Enrollment Summary service. It lists the objects inside a device that have been configured to generate event notifications (intrinsic or algorithmic) to a particular notification class or recipient, filtered by the parameters supplied in the request.

    BACnet.Protocol.EventInformation

    Event Information is the rich data structure returned by the Get Event Information service (ASHRAE 135 Clause 13.12). It is the modern replacement for the older Get Alarm Summary service and is the recommended way for a client to obtain a complete picture of every object in a device that is capable of generating events.

    BACnet.Protocol.EventLogRecord

    An Event Log Record is the structure stored by an Event Log object every time it receives (or generates) an event notification. It captures the timestamp, the full Confirmed Event Notification that was processed, the log status or any time change, at the moment the record was created.

    BACnet.Protocol.EventMessageTexts

    Event Message Texts is a simple triple of character strings that a device can use to supply human-readable messages for each of the three possible event state transitions. The three fields correspond to the messages that should be sent when the object transitions to-Offnormal, to-Fault, and to-Normal.

    A Foreign Device Table Entry represents one foreign device that has registered with a BACnet/IP Broadcast Management Device (BBMD). Foreign devices use this registration mechanism to participate in BACnet broadcasts even when they are not on the same IP subnet as the devices they need to communicate with.

    BACnet.Protocol.GroupChannelValue

    A Group Channel Value is the payload element used by the Write Group service. It allows a single confirmed or unconfirmed request to command many objects at once by addressing them through a numeric "channel" rather than by object identifier.

    BACnet.Protocol.IncompleteAPDU

    This module is used to represent a segmented incomplete APDU.

    BACnet.Protocol.LimitEnable

    BACnet Limit Enable is a two-bit bit string that controls which of the intrinsic or algorithmic limit-detection mechanisms are active for an object (primarily Analog Input/Value, Large Analog Value, etc.).

    BACnet.Protocol.LogMultipleRecord

    A Log Multiple Record is the data element used by Trend Log Multiple objects. Unlike a normal Trend Log (which records a single point over time), a Trend Log Multiple records several properties from one or more objects at the same instant, producing a "row" of related samples.

    BACnet.Protocol.LogRecord

    A Log Record is the basic unit stored inside the buffer of a Trend Log or Event Log object. Every time a trend log collects a sample, or an event log records an event notification, a Log Record is appended to the circular buffer.

    BACnet.Protocol.LogStatus

    Log Status is a compact three-bit bit string that reports the operational state of a Trend Log or Event Log object. The three bits respectively indicate whether logging has been disabled by the Log_Enable property, whether the internal buffer has been purged since the last notification, and whether logging was interrupted (for example because of a power failure or a configuration change).

    BACnet.Protocol.NPCI

    Network Protocol Control Information (NPCI) is the header that precedes every BACnet Network Protocol Data Unit (NPDU). It carries the information that BACnet routers and receiving devices need to correctly forward or deliver the message.

    BACnet.Protocol.NameValue

    BACnetNameValue is a structure used primarily for the Tags property (of type BACnetARRAY of BACnetNameValue) that exists on nearly every standardized BACnet object type (ASHRAE 135-2016 Clause 12.x and Annex Y).

    BACnet.Protocol.ObjectOperations

    Shared operations for BACnet object structs.

    BACnet.Protocol.ObjectPropertyRef

    An Object Property Reference is the most common way to name a specific property of a specific object in BACnet. It consists of an Object Identifier, a Property Identifier (which may be a standard named property or a vendor-specific numeric identifier), and an optional array index when the property is an array.

    BACnet.Protocol.ObjectTypes.Accumulator

    The Accumulator counts pulses from equipment such as an electricity, water or gas meter. Present_Value holds the running count. Prescale controls how many input pulses contribute to it, and Max_Pres_Value sets the rollover point. Optional properties report the pulse rate, record when the count was preset, or capture a sample for a logger.

    BACnet.Protocol.ObjectTypes.AnalogInput

    The Analog Input object is the primary BACnet object type for exposing continuous sensor measurements such as temperature, pressure, flow, humidity, current, voltage, or any other physical analog quantity. Supply the reading in the engineering units given by units. The object exposes it through present_value and can report the sensor's range, resolution, update interval and reliability.

    BACnet.Protocol.ObjectTypes.AnalogOutput

    An Analog Output holds the command for an actuator such as a valve, damper or variable-speed drive. Its present_value is the highest-priority active command. When all 16 slots in the priority_array are empty, it uses relinquish_default.

    BACnet.Protocol.ObjectTypes.AnalogValue

    An Analog Value is used for an application value such as a setpoint, tuning constant or intermediate calculation. Both the local application and BACnet clients can write present_value, subject to the object's commandability and write rules.

    BACnet.Protocol.ObjectTypes.Averaging

    An Averaging object tracks the minimum, maximum and arithmetic mean of a property over a moving window. It can also report variance and the timestamps of the extrema. For example, sample the same temperature periodically to see how far it varies over the last hour.

    BACnet.Protocol.ObjectTypes.BinaryInput

    A Binary Input represents a two-state sensor or contact, such as a door switch or a pump run signal. Its Boolean present_value is the logical reading after applying polarity. Use device_type to describe the connected hardware.

    BACnet.Protocol.ObjectTypes.BinaryOutput

    A Binary Output commands a two-state actuator such as a relay or solenoid valve. The priority array selects the effective command in present_value. The driver can use get_output/2 to obtain the signal for the configured normal or reverse polarity.

    BACnet.Protocol.ObjectTypes.BinaryValue

    A Binary Value holds an application flag such as an enable command, an alarm latch or a calculated Boolean result. BACnet clients can read and, where permitted, write its logical state. The object can also track transitions, active time and minimum on/off durations.

    BACnet.Protocol.ObjectTypes.BitstringValue

    A Bitstring Value groups Boolean flags into one named BACnet value. For example, use it to publish a set of related alarm bits. In Elixir, the value is a tuple of booleans. Optional labels describe what each bit means.

    BACnet.Protocol.ObjectTypes.Calendar

    A Calendar lists dates, ranges or patterns that mark days such as holidays. Its Present_Value tells clients whether the device's current local date matches an entry. Several Schedule objects can reference the same Calendar to share one list of exceptions.

    BACnet.Protocol.ObjectTypes.CharacterStringValue

    A Character String Value exposes text such as an equipment label, operator message or configuration setting over BACnet. The Elixir value is a UTF-8 string.

    BACnet.Protocol.ObjectTypes.Command

    A Command runs a predefined sequence of property writes from a single request. Writing an action code to present_value selects the sequence to run. For example, an occupied-mode action could set the lighting level and temperature setpoint for a zone.

    BACnet.Protocol.ObjectTypes.DatePatternValue

    A Date Pattern Value stores a BACnet date pattern, such as every Monday or the last day of even months. Use BACnet.Protocol.ObjectTypes.DateValue when the value is a single date or a fully unspecified date.

    BACnet.Protocol.ObjectTypes.DateTimePatternValue

    A DateTime Pattern Value stores a combined date and time pattern, such as 17:00 on the last day of even months. Use BACnet.Protocol.ObjectTypes.DateTimeValue for a single date and time.

    BACnet.Protocol.ObjectTypes.DateTimeValue

    A DateTime Value exposes a timestamp such as a service deadline or a process's next planned run. It holds a fully specified date and time or a fully unspecified value. The application decides when to act on it.

    BACnet.Protocol.ObjectTypes.DateValue

    A Date Value holds a calendar date, such as a warranty expiry or the date of the last service. The date can be fully specified or fully unspecified.

    BACnet.Protocol.ObjectTypes.Device

    A Device object identifies a BACnet device and exposes its capabilities and operating state. Its object identifier distinguishes the device from other devices on the BACnet internetwork.

    BACnet.Protocol.ObjectTypes.EventEnrollment

    An Event Enrollment monitors a property on a local or remote object. Use one to report events for a source that lacks its own intrinsic reporting. The enrollment holds the algorithm configuration and event state and refers to a Notification Class for delivery.

    BACnet.Protocol.ObjectTypes.EventLog

    An Event Log stores timestamped BACnet.Protocol.Services.ConfirmedEventNotification and BACnet.Protocol.Services.UnconfirmedEventNotification records. Use BACnet.Protocol.Services.ReadRange to retrieve the alarm and event history.

    BACnet.Protocol.ObjectTypes.File

    A File object exposes data that a BACnet client can transfer using BACnet.Protocol.Services.AtomicReadFile or BACnet.Protocol.Services.AtomicWriteFile. Read its metadata to learn the size, access method and modification time. Use its object identifier in the transfer request.

    BACnet.Protocol.ObjectTypes.Group

    A Group gathers properties from local objects so a client can read them together. For example, a room's Group could expose the temperature, setpoint and occupancy from three different objects. A read of present_value returns a value or access error for each selected property.

    BACnet.Protocol.ObjectTypes.IntegerValue

    An Integer Value holds signed application data such as a counter that can go below zero, an error code or a sequence step. Clients can read the current value and write it when the application allows it.

    BACnet.Protocol.ObjectTypes.LargeAnalogValue

    A Large Analog Value holds a double-precision floating-point number. Use it for quantities such as accumulated energy totals that need more precision than a single-precision Analog Value offers.

    BACnet.Protocol.ObjectTypes.Loop

    A Loop represents a feedback controller. For example, it can compare a room temperature with its setpoint and command a heating valve. The object exposes the measured value, setpoint, tuning and limits. Its present_value is the control output in output_units.

    BACnet.Protocol.ObjectTypes.MultistateInput

    A Multistate Input reports one of several states, such as a valve's closed, midway or open position. State numbers start at 1. Use the optional state_text array to label them, with the first entry describing state 1.

    BACnet.Protocol.ObjectTypes.MultistateOutput

    A Multistate Output commands a device with a fixed set of states, such as a fan with several speeds. The effective command in present_value is a state number between 1 and Number_Of_States. Optional state_text entries give each state a label.

    BACnet.Protocol.ObjectTypes.MultistateValue

    A Multistate Value represents an application mode, stage or sequence position. Its value is a state number between 1 and Number_Of_States. The application defines what each number means and can expose labels through state_text.

    BACnet.Protocol.ObjectTypes.NetworkPort

    A Network Port exposes a device's communication settings and status through BACnet. A client can read the port configuration and request supported changes. The application connects those requests to its running transport.

    BACnet.Protocol.ObjectTypes.NotificationClass

    A Notification Class determines where an event notification should go and how to send it. Event sources reference the class by its Notification_Class number. The class defines these settings.

    BACnet.Protocol.ObjectTypes.OctetStringValue

    An Octet String Value holds an Elixir binary and exposes each byte over BACnet. Use it for data such as a certificate or a binary configuration payload. The producer and consumer define the payload format.

    BACnet.Protocol.ObjectTypes.PositiveIntegerValue

    A Positive Integer Value holds an unsigned integer such as a pulse total, error count or stage number. It accepts zero. Use BACnet.Protocol.ObjectTypes.IntegerValue when the value can be negative.

    BACnet.Protocol.ObjectTypes.Program

    A Program exposes the state of an application program, script or state machine to BACnet clients. Clients read program_state and use program_change to request actions such as loading, running or halting it. Optional properties describe why it halted and identify the loaded program.

    BACnet.Protocol.ObjectTypes.PulseConverter

    A Pulse Converter turns a pulse count into a quantity such as energy or water usage. It can accept batches of pulses or read a counter on another object. Present_Value is Count multiplied by Scale_Factor.

    BACnet.Protocol.ObjectTypes.Schedule

    A Schedule selects a value from a weekly timetable or an exception and writes it to configured BACnet properties. Use one for occupancy setpoints, lighting scenes or holiday overrides. Several schedules can share a holiday list through a BACnet.Protocol.ObjectTypes.Calendar.

    BACnet.Protocol.ObjectTypes.StructuredView

    A Structured View organizes object references into a hierarchy that clients can browse, such as floor, air handler and supply temperature. The node_type and node_subtype describe the kind of node. The subordinate_list holds references to its children, which can themselves be Structured Views.

    BACnet.Protocol.ObjectTypes.TimePatternValue

    A Time Pattern Value stores a BACnet time pattern, such as the half-hour mark of every hour. Use BACnet.Protocol.ObjectTypes.TimeValue when the value represents a single time of day.

    BACnet.Protocol.ObjectTypes.TimeValue

    A Time Value holds a time of day such as occupancy start or night setback. The time can be fully specified or fully unspecified.

    BACnet.Protocol.ObjectTypes.TrendLog

    A Trend Log records timestamped samples of one local or remote property. Configure the source in log_device_object_property and choose how to sample it - on a timer, on change of value, or on demand.

    BACnet.Protocol.ObjectTypes.TrendLogMultiple

    A Trend Log Multiple captures related readings in one record. For example, sample supply temperature, return temperature, valve position and airflow together. Each record has one timestamp and a value or failure for each configured reference.

    BACnet.Protocol.Prescale

    A Prescale is a simple multiplier / modulo-divide pair used by Accumulator objects to scale the raw pulse count coming from a physical meter into the engineering units that the present value property should report.

    BACnet.Protocol.PriorityArray

    The Priority Array is a BACnet means of ensuring Command Prioritization. The Priority Array is an array (or in this case a struct) that contains 16 levels of priority, each which can take a particular value (each priority must have the same type) or NULL (nil). The highest priority (lowest array index) with a non-NULL value is the active command.

    BACnet.Protocol.PropertyRef

    A Property Reference names only a property (and optionally an array index) without identifying the object that contains it. It is used in contexts where the object is already known from surrounding context.

    BACnet.Protocol.PropertyState

    Property State is a large CHOICE used to carry the value of almost any property in event and fault algorithms (Change-of-State, Command-Failure, various fault detectors, etc.).

    BACnet.Protocol.PropertyValue

    Property Value packages a property reference (identifier + optional array index) together with the value to be written (or that was read). It is the basic payload element inside WritePropertyMultiple, ReadPropertyMultiple results, and several action / event parameter structures.

    BACnet.Protocol.ReadAccessResult

    A Read Access Result is the response data returned for one object when a Read Property Multiple request is processed. It contains the Object Identifier of the object that was read, followed by a list of individual property results (which may contain either a successful value or an error for that specific property).

    BACnet.Protocol.ReadAccessResult.ReadResult

    Represents the result of reading one specific property as part of a Read Property Multiple response.

    BACnet.Protocol.Recipient

    A Recipient identifies the target of an event notification or a COV notification. It is a CHOICE between either a specific device (identified by its Device object identifier) or a network address (which may be a unicast address, a broadcast address, or a remote network broadcast).

    BACnet.Protocol.RecipientAddress

    A Recipient Address is the low-level network addressing information used when a BACnet device needs to send an event notification or COV notification to a specific location rather than to a known Device object identifier.

    BACnet.Protocol.ResultFlags

    BACnet Result Flags is a three-bit bit string returned by range-reading services (ReadRange, GetEventInformation, etc.) to describe the window of data that was actually returned.

    BACnet.Protocol.RouterEntry

    A BACnetRouterEntry describes one first-hop router that can be used to reach a remote BACnet network.

    BACnet.Protocol.Services.Ack.GetEnrollmentSummaryAck

    BACnet.Protocol.SetpointReference

    A Setpoint Reference is a nullable pointer to another property that should be treated as the setpoint for a control loop object (Loop, Analog Output, etc.).

    BACnet.Protocol.SpecialEvent

    A Special Event defines an exception that overrides the normal weekly schedule on selected days. It is the mechanism Schedule objects use for holidays, maintenance windows, after-hours operation, etc.

    BACnet.Protocol.StatusFlags

    BACnet Status Flags is a four-bit bit string (application tag 8) that provides a compact summary of an object's health and operating mode. It is the status_flags property on virtually every standard object type and appears in almost every event-related structure.

    BACnet.Protocol.TimeValue

    A Time Value is the atomic (time, value) pair used inside BACnet.Protocol.DailySchedule entries. It says: "at (or after) this time, the scheduled property should take on this value".

    BACnet.Protocol.WeekNDay

    A WeekNDay (Week And Day) is a compact 3-component pattern used inside BACnet.Protocol.CalendarEntry and BACnet.Protocol.SpecialEvent to describe recurring days without listing every date. Classic examples: "the third Tuesday of every month", "every Friday", or "the last Sunday in odd months".
