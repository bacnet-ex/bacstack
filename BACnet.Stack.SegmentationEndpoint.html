    BACnet.Stack.SegmentationEndpoint (bacstack v0.1.0-dev.2)

    View Source

    Identifies a remote endpoint for segmented transfers on a particular transport portal.

    Both segmentation components use this identity together with the local transaction role (:requester or :responder) and invoke ID. The transport module and portal distinguish local links; address identifies the transport peer and npci contains the complete routed network/address pair, when present.

    Construct the endpoint with the same transport send options used to create the sequence. For incoming traffic, pass the NPCI source as the :destination option. For a forwarded BACnet/IP NPDU, use its originating IP/port as the peer address, as replies go to that peer. Device object instance numbers are not part of this routing identity.

    Roles belong to sequence keys, so the same endpoint can participate in both roles concurrently.

    Determines the local transaction role for a received APDU or reassembly fragment.

    Returns :requester when the local device initiated the confirmed transaction, or :responder when the peer initiated it.

    Received dataFlagLocal role
    IncompleteAPDU containing a confirmed-request fragmentserver: true:responder
    IncompleteAPDU containing a ComplexACK fragmentserver: false:requester
    Abort or SegmentACK from the remote serversent_by_server: true:requester
    Abort or SegmentACK from the remote clientsent_by_server: false:responder
    Error, Reject, or SimpleACKNo server flag:requester

    IncompleteAPDU.server describes the local receiving role. In contrast, sent_by_server on Abort and SegmentACK describes the remote sender's role, so the local role is the opposite. Error, Reject, and SimpleACK are always responses to a locally initiated request.
