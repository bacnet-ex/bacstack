    BACnet.Protocol.ObjectTypes.Program (bacstack v0.1.0-dev.2)

    View Source

    A Program exposes the state of an application program, script or state machine to BACnet clients. Clients read program_state and use program_change to request actions such as loading, running or halting it. Optional properties describe why it halted and identify the loaded program.

    The object deliberately leaves the actual program logic and any additional parameters as vendor-specific. It is the standard way to monitor and control embedded control logic, custom sequences, or downloadable applications from a BACnet workstation.

    Object Description (ASHRAE 135)

    The Program object type defines a standardized object whose properties represent the externally visible characteristics of an application program.

    Program objects that support intrinsic reporting shall apply the NONE event algorithm.

    Behaviour and Operation

    program_state reflects the runtime's current state. A write to program_change requests a transition. The object accepts another request when Program_Change is :ready. Requests that keep the program in its current state complete immediately.

    Starting from idle loads the program and then initializes it at its entry point. Load or Restart on an initialized running program reenters that entry point. Run resumes a halted, initialized program. If a halt interrupted loading, Restart loads the incomplete program again. Out_Of_Service indicates whether the program is properly loaded and initialized. A waiting or halted program can remain in service. When selected, Reason_For_Halt and Description_Of_Halt expose why execution stopped.

    Lifecycle

    The object execution host retains the object and execution state returned by each step. Use BACnet.Protocol.ObjectExecution.Lifecycle.prepare_write/3 to prepare a Program_Change write, then execute the committed candidate. A busy request returns {:error, :busy} before any runtime operation. A local override indicated by Status_Flags also prevents BACnet writes to program settings.

    Supply a runtime/0 callback as the :program_runtime option to create/4 for a local Program that runs runtime actions. The object retains the binding in its metadata. When recreating a persisted object at startup, supply the callback from local application configuration.

    Commit the result, then run its immediate continuation to invoke the runtime. The callback can finish during that call or return :pending. For a pending action, deliver its token and outcome through the :program_event option in BACnet.Protocol.ObjectExecution.Context on a :periodic step. Report a failure through the same option if the action times out.

    Use the same event option to report runtime waits, resumes, halts and location changes. See runtime_event/0 for the supported inputs. A runtime halt can terminate an incomplete load, and a completion for a superseded operation leaves the current operation intact.

    On startup, supply properties that reflect the runtime's current state. Initialization clears any saved request without replaying it. The runtime runs the program and manages its I/O and resources. Remote snapshots retain their stored values.

    With intrinsic_reporting: true, changes in Reliability can generate FAULT and NORMAL transitions. After committing the result, call BACnet.Protocol.ObjectExecution.EventReporting.transition/1 to retrieve them.

    Examples

    Creating a Program object:

    iex> {:ok, p} = BACnet.Protocol.ObjectTypes.Program.create(1400, "MyApp", %{program_state: :idle}); p.object_name
"MyApp"

    Loading and starting a program with an asynchronous load:

    iex> alias BACnet.Protocol.ObjectExecution.{Context, Lifecycle}
iex> alias BACnet.Protocol.ObjectTypes.Program
iex> runtime = fn
...>   :load, token, _object ->
...>     send(self(), {:loading, token})
...>     :pending
...>   :restart, _token, _object -> :ok
...> end
iex> {:ok, object} = Program.create(1400, "MyApp", %{program_state: :idle}, program_runtime: runtime)
iex> context = Context.new(:initialization)
iex> {:ok, stored} = Lifecycle.execute(object, context)
iex> write = %{context | state: stored.state, trigger: {:property_write, :program_change, nil, nil}}
iex> {:ok, candidate} = Program.update_property(stored.object, :program_change, :run)
iex> {:ok, prepared} = Lifecycle.prepare_write(stored.object, candidate, write)
iex> {:ok, staged} = Lifecycle.execute(prepared, write)
iex> {staged.object.program_state, staged.object.program_change, staged.next_execution}
{:loading, :run, :immediate}
iex> {:ok, waiting} = Lifecycle.execute(staged.object, %{context | trigger: :continuation, state: staged.state})
iex> token = receive do {:loading, token} -> token end
iex> completion = Context.new(:periodic, state: waiting.state,
...>   options: [program_event: {:completed, token, :ok}])
iex> {:ok, loaded} = Lifecycle.execute(waiting.object, completion)
iex> {:ok, running} = Lifecycle.execute(loaded.object, %{context | trigger: :continuation, state: loaded.state})
iex> {running.object.program_state, running.object.program_change, running.object.out_of_service}
{:running, :ready, false}

    WriteProperty without a runtime binding

    This example shows the host handling a request to write RUN to Program_Change on an idle Program. The host resolves the request to the stored local object and checks property access before preparing the candidate. For this example, the host maps a missing runtime binding to PROPERTY/WRITE_ACCESS_DENIED in a BACnet.Protocol.APDU.Error response.

    iex> alias BACnet.Protocol.{Constants, ObjectsUtility}
iex> alias BACnet.Protocol.ApplicationTags.Encoding
iex> alias BACnet.Protocol.APDU.Error
iex> alias BACnet.Protocol.ObjectExecution.{Context, Lifecycle}
iex> alias BACnet.Protocol.ObjectTypes.Program
iex> alias BACnet.Protocol.Services.WriteProperty
iex> {:ok, object} = Program.create(1400, "MyApp", %{program_state: :idle})
iex> {:ok, stored} = Lifecycle.execute(object, Context.new(:initialization))
iex> request = %WriteProperty{
...>   object_identifier: Program.get_object_identifier(stored.object),
...>   property_identifier: :program_change,
...>   property_array_index: nil,
...>   property_value: Encoding.create!({:enumerated, Constants.by_name!(:program_request, :run)}),
...>   priority: nil
...> }
iex> {:ok, apdu} = WriteProperty.to_apdu(request, invoke_id: 7)
iex> {:ok, write} = WriteProperty.from_apdu(apdu)
iex> true = write.object_identifier == Program.get_object_identifier(stored.object)
iex> true = Program.property_writable?(stored.object, write.property_identifier)
iex> {:ok, :run = value} = ObjectsUtility.cast_property_to_value(
...>   write.object_identifier, write.property_identifier, write.property_value
...> )
iex> {:ok, candidate} = Program.update_property(stored.object, write.property_identifier, value)
iex> trigger = {:property_write, write.property_identifier, write.property_array_index, write.priority}
iex> context = Context.new(trigger, state: stored.state)
iex> {:error, {:unsupported_operation, :program_runtime}} = Lifecycle.prepare_write(stored.object, candidate, context)
iex> response = %Error{invoke_id: apdu.invoke_id, service: apdu.service, class: :property, code: :write_access_denied, payload: []}
iex> Error.encode(response)
{:ok, <<0x50, 7, 0x0F, 0x91, 2, 0x91, 0x28>>}
iex> {stored.object.program_state, stored.object.program_change}
{:idle, :ready}

    The preparation error leaves the stored result intact. A request that keeps the program in its current state, such as HALT while idle, can complete without a runtime binding. The host can acknowledge that write with BACnet.Protocol.APDU.SimpleACK after executing it.

    common_object_opts()

    @type common_object_opts() ::
  {:allow_numeric_constants, boolean()}
  | {:allow_unknown_properties, boolean()}
  | {:ignore_unknown_properties, boolean()}
  | {:revision,
     BACnet.Protocol.Constants.protocol_revision() | non_neg_integer()}
  | {:skip_property_validation_remote_object, boolean() | :value}

    Common object options for creation - all are optional.

    • allow_numeric_constants - Constants are atoms and thus unknown constants or vendor extensions are integers and thus are rejected. Enabling this option will allow integers (non_neg_integer()) for properties with a Constants.type() spec.
    • allow_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties (numeric identifiers usually means we dont know them) are accepted and put into a separate map. This does mean we can not validate or write them. Types of the values can be anything at this point. While you can read unknown properties with atom or integer as property identifier, you can only remove numeric unknown property identifiers from an object. Property identifiers of type atom are only accepted, if it is a remote object (object implementation is only enforced if it is a local object). Numeric property identifiers are accepted regardless of remote object or not. For remote objects, this means you have to write "raw values" (usually BACnet.Protocol.ApplicationTags.Encoding structs).
    • ignore_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties get ignored, as if they were not specified.
    • revision - The BACnet protocol revision used for required properties and annotation conditions. Accepts a non-negative protocol revision number (for example, 19) or a name from BACnet.Protocol.Constants.protocol_revision/0. Optional properties remain available unless an annotation prohibits them. Default required annotations use ASHRAE 135-2012 (revision 14), or the addendum/revision that introduced a later object type.
    • skip_property_validation_remote_object - Skips property validation for remote objects. Sometimes it is possible that the value is invalid as per BACnet specification (i.e. value 0 for a multistate object), but you still want those to be represented. Value true neither type nor value are validated. Value :value means the type is still validated and only the value validator is not run (if present). The property's validator_fun will also be skipped.
