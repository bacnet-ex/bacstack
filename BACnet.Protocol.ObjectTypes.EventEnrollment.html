    BACnet.Protocol.ObjectTypes.EventEnrollment (bacstack v0.1.0-dev.2)

    View Source

    An Event Enrollment monitors a property on a local or remote object. Use one to report events for a source that lacks its own intrinsic reporting. The enrollment holds the algorithm configuration and event state and refers to a Notification Class for delivery.

    Object Description (ASHRAE 135)

    The Event Enrollment object type defines a standardized object that represents and contains the information required for algorithmic reporting of events. For the general event concepts and algorithmic event reporting, see Clause 13.2.

    Behaviour and Operation

    object_property_reference selects the value to monitor. event_parameters selects the event algorithm and its inputs. An optional fault_parameters selects the fault algorithm. The object derives event_type and fault_type from those parameters. The enrollment only reads the monitored object.

    The object execution host supplies the :read_property callback in BACnet.Protocol.ObjectExecution.Context. The enrollment passes local and device-qualified references to that callback, including any array index. For remote monitoring, the host can use BACnet.Stack.ClientHelper.read_property/5 and return the property's native value. For an optional property that is absent, return an unknown-property error. The enrollment also reads inputs selected by the algorithm, such as the monitored object's status flags, a feedback or setpoint reference, or a life safety mode.

    Execute when the enrollment starts, an input changes, a configuration write commits or a timer comes due. For a remote source, the host can also poll with :periodic. Retain each result and schedule any requested monotonic deadline. The algorithm uses monotonic time to measure delays and local wall time for event timestamps and Notification Class delivery windows. A property read returns the last evaluated state and preserves any pending deadline.

    Reliability and inhibition

    Acquisition and configuration failures take precedence over a fault reported by the monitored object, which takes precedence over the optional fault algorithm. Fault transitions take precedence over offnormal events. An initialized event_algorithm_inhibit_ref controls the inhibit flag from a local Boolean or BinaryPV property. Inhibition returns an offnormal event to NORMAL and starts a fresh delay when released. Fault detection can continue while the event algorithm is inhibited. reliability_evaluation_inhibit suppresses reliability evaluation. Disabling event_detection_enable resets event state, timestamps, messages and acknowledgment bits and clears the retained event and fault algorithm states.

    Transitions and delivery

    Each transition updates its event timestamp, message and acknowledgment bit. The enrollment uses BACnet.Protocol.ObjectExecution.Context.lookup_object/2 to find the Notification Class, which provides the eligible recipients and acknowledgment requirement. If lookup fails, the enrollment records the transition with a nil routing plan and no acknowledgment requirement.

    After committing the result, call transition/1 to get the recorded transition. For an enabled transition with a routing plan, the host builds either a BACnet.Protocol.Services.ConfirmedEventNotification or an BACnet.Protocol.Services.UnconfirmedEventNotification for each recipient. To process an alarm acknowledgment, the host validates the acknowledged event state and uses acknowledge/3 to match the last timestamp and update the bit. It handles delivery of the resulting acknowledgment notification.

    The lifecycle supports NONE and the implemented standard event and fault algorithms. An enabled enrollment with a vendor-specific Extended algorithm returns an unsupported-algorithm error.

    Example

    Monitor an unsigned Present_Value and hold the high-limit condition for five seconds before emitting a transition.

    iex> alias BACnet.Protocol.{DeviceObjectPropertyRef, EventParameters, ObjectIdentifier, StatusFlags}
iex> alias BACnet.Protocol.ObjectExecution.{Context, Lifecycle}
iex> alias BACnet.Protocol.ObjectTypes.{EventEnrollment, NotificationClass}
iex> reference = %DeviceObjectPropertyRef{
...>   device_identifier: nil,
...>   object_identifier: %ObjectIdentifier{type: :positive_integer_value, instance: 2},
...>   property_identifier: :present_value,
...>   property_array_index: nil
...> }
iex> {:ok, enrollment} = EventEnrollment.create(1100, "High value", %{
...>   notification_class: 1,
...>   object_property_reference: reference,
...>   event_parameters: %EventParameters.UnsignedRange{
...>     low_limit: 1, high_limit: 10, time_delay: 5, time_delay_normal: nil
...>   }
...> })
iex> {:ok, class} = NotificationClass.create(1, "Alarms", %{notification_class: 1})
iex> read = fn
...>   %{property_identifier: :present_value} -> {:ok, 12}
...>   %{property_identifier: :reliability} -> {:ok, :no_fault_detected}
...>   %{property_identifier: :status_flags} -> {:ok, StatusFlags.from_bitstring({false, false, false, false})}
...> end
iex> now = ~U[2026-06-01 12:00:00Z]
iex> context = Context.new(:initialization,
...>   now: now, monotonic_time: 0, read_property: read,
...>   lookup_object: fn _reference -> {:ok, class} end
...> )
iex> {:ok, pending} = Lifecycle.execute(enrollment, context)
iex> pending.next_execution.monotonic_time
5000
iex> timer = %{context | trigger: :timer, now: DateTime.add(now, 5, :second),
...>   monotonic_time: 5000, state: pending.state}
iex> {:ok, evaluated} = Lifecycle.execute(pending.object, timer)
iex> evaluated.object.event_state
:high_limit
iex> EventEnrollment.transition(evaluated).transition
:to_offnormal

    common_object_opts()

    @type common_object_opts() ::
  {:allow_numeric_constants, boolean()}
  | {:allow_unknown_properties, boolean()}
  | {:ignore_unknown_properties, boolean()}
  | {:revision,
     BACnet.Protocol.Constants.protocol_revision() | non_neg_integer()}
  | {:skip_property_validation_remote_object, boolean() | :value}

    Common object options for creation - all are optional.

    • allow_numeric_constants - Constants are atoms and thus unknown constants or vendor extensions are integers and thus are rejected. Enabling this option will allow integers (non_neg_integer()) for properties with a Constants.type() spec.
    • allow_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties (numeric identifiers usually means we dont know them) are accepted and put into a separate map. This does mean we can not validate or write them. Types of the values can be anything at this point. While you can read unknown properties with atom or integer as property identifier, you can only remove numeric unknown property identifiers from an object. Property identifiers of type atom are only accepted, if it is a remote object (object implementation is only enforced if it is a local object). Numeric property identifiers are accepted regardless of remote object or not. For remote objects, this means you have to write "raw values" (usually BACnet.Protocol.ApplicationTags.Encoding structs).
    • ignore_unknown_properties - Properties that are unknown to the object implementation are usually rejected. With this option, unknown properties get ignored, as if they were not specified.
    • revision - The BACnet protocol revision used for required properties and annotation conditions. Accepts a non-negative protocol revision number (for example, 19) or a name from BACnet.Protocol.Constants.protocol_revision/0. Optional properties remain available unless an annotation prohibits them. Default required annotations use ASHRAE 135-2012 (revision 14), or the addendum/revision that introduced a later object type.
    • skip_property_validation_remote_object - Skips property validation for remote objects. Sometimes it is possible that the value is invalid as per BACnet specification (i.e. value 0 for a multistate object), but you still want those to be represented. Value true neither type nor value are validated. Value :value means the type is still validated and only the value validator is not run (if present). The property's validator_fun will also be skipped.
