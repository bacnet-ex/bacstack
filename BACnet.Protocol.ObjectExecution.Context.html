    BACnet.Protocol.ObjectExecution.Context (bacstack v0.1.0-dev.2)

    View Source

    Inputs and host operations for one BACnet object execution step.

    The caller supplies a fresh context for each call to BACnet.Protocol.ObjectsProtocol.execute/2:

    • now is the current wall time in the device's configured time zone. Use it for calendar and schedule calculations. Execution never reads the clock implicitly.
    • monotonic_time is the current monotonic time in milliseconds. Use it for elapsed durations and delays, which must not be affected by wall-clock adjustments. Its origin is arbitrary and its value may be negative.
    • trigger identifies why execution was requested: :periodic, :initialization, :clock_change, or {:property_write, property_identifier, array_index, priority}. A property write trigger is supplied after a successful write, with the updated object, even if the written value equals the previous value. Index and priority are nil when omitted. Invoke execution for each write before applying the next one, so the object contains the value for that trigger. The host delivers triggers; object property functions do not invoke execute/2 themselves.
    • state is opaque runtime state owned by the object module. Supply nil for the first execution and the previous result's state on subsequent calls. Keep this state separately for each object instance; it is not a BACnet property and is not stored in the object's metadata. Monotonic timestamps in state are only meaningful within the same VM lifetime.
    • lookup_object, read_property, and write_property are optional host callbacks. They provide access to local or remote objects; they do not replace the executing object's behaviour. The helper functions in this module report {:error, {:unsupported_operation, operation}} when a callback is absent.
    • options holds object-specific configuration, documented by the object module. Common inputs above must use their named fields.

    References retain their device identifier and property array index. A missing device identifier denotes the executing object's local device. The host resolves references, checks access, handles transport and converts values to/from the Elixir property representations used by object modules. A write with priority nil has no explicit priority; it does not mean relinquish.

    Callbacks run synchronously in the executing process and return their results directly. They must bound any network waits. Exceptions and malformed callback results are programming errors and are not converted into operational errors. Writes take effect when the callback runs; execution offers no rollback. Callbacks must avoid calling back into a server that is blocked executing the object (for example, calling the same GenServer synchronously).
