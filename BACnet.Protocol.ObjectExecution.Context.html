    BACnet.Protocol.ObjectExecution.Context (bacstack v0.1.0-dev.2)

    View Source

    Inputs and host operations for one BACnet object execution step. Clock samples, prior state and host callbacks for a lifecycle operation.

    The object execution host is the integrating application or higher-level BACnet stack that owns object instances and drives their lifecycle. That central contract defines the host responsibilities referred to here.

    Use new/2 to build a context from a trigger and keyword options. For an existing instance, pass the last BACnet.Protocol.ObjectExecution.Result's state as state:. Use the same clock samples for write preparation, execution and nested reads in one operation. For the next operation or an immediate continuation, build a new context with fresh samples and carry forward any host callbacks and options the instance needs.

    • now is the current wall time in the device's configured timezone. Lifecycle calculations use this sample. Backends such as BACnet.Stack.TrendLogger sample their configured clocks for record timestamps and collection windows.
    • timezone_database is the Calendar.TimeZoneDatabase module used to resolve future local deadlines, including timezone transitions. new/2 uses Calendar.get_time_zone_database/0 unless overridden. Regional zones need a database that supports them. Execution uses the database retained in the context.
    • monotonic_time is the current monotonic time in milliseconds. Use it for elapsed durations and delays, which must not be affected by wall-clock adjustments. Its origin is arbitrary and its value may be negative.
    • trigger identifies why the host called the lifecycle. See entry points and triggers for when to use each trigger/0. In a write trigger, the array index and priority are nil when omitted. Preserve the write's origin - a local callback handling a BACnet command still uses :property_write. The object module documents how it handles application writes, including physical input, feedback and out-of-service simulation.
    • state is opaque runtime state owned by the object module. Supply nil for the first execution and the previous result's state on subsequent calls. Keep this state separately for each object instance - it is not a BACnet property and is not stored in the object's metadata. Monotonic timestamps in state are only meaningful within the same VM lifetime.
    • lookup_object, read_property, read_property_multiple and write_property are optional host callbacks. They provide access to local or remote objects - they do not replace the executing object's behaviour. The helper functions in this module report {:error, {:unsupported_operation, operation}} when a callback is absent.
    • options holds object-specific inputs, documented by the object module. For a qualified Logging_Record read on BACnet.Protocol.ObjectTypes.Accumulator, the host supplies the local reading object's identifier as :reader_identifier. Common inputs above must use their named fields.

    device_identifier is the local Device ObjectIdentifier, or nil when not needed. Supply the identifier when an object needs to distinguish an explicitly addressed self-device reference from a remote reference. Schedule normalizes recognized self references to local host operations and forwards other device-qualified references unchanged. Without a local identity, qualified references are forwarded as remote references. All struct fields must be supplied explicitly, including those set to nil. Use new/2 to initialize every field from an explicit trigger and keyword fields, with fresh clock samples and common initial values for omitted fields.

    References retain their device identifier and property array index. A missing device identifier denotes the executing object's local device. The host needs to resolve references, check access, handle transport and apply writes. Write callbacks may receive an BACnet.Protocol.ApplicationTags.Encoding, a list of encodings, or an object's Elixir value, as documented by the executing object module. Schedule supplies encodings. Local adapters can decode them through BACnet.Protocol.ObjectsUtility.cast_property_to_value/4 using the target object identifier and allow_partial: true for array elements. NULL command relinquishment and array length writes need to be handled by the local write path before ordinary property casting. Remote adapters can forward encodings directly to BACnet.Stack.ClientHelper.write_property/6. A write with priority nil has no explicit priority - it does not mean relinquish.

    read_property_multiple accepts a device/object reference and a list of properties or selectors, and returns a map of property identifiers to native values. Indexed results use {property_identifier, array_index} keys. Per-property failures use {:error, reason} values. Selectors follow ReadPropertyMultiple rules - see BACnet.Protocol.ObjectTypes.Group. Group converts these native values and builds its own BACnet.Protocol.ReadAccessResult values.

    Callbacks run synchronously in the executing process and return their results directly. They must bound any network waits. Exceptions and malformed callback results are programming errors and are not converted into operational errors. Writes take effect when the callback runs - execution offers no rollback. Callbacks must avoid calling back into a server that is blocked executing the object (for example, calling the same GenServer synchronously).

    new(trigger, fields \\ [])

    @spec new(trigger(), [init_option()]) :: t()

    Builds a context from a trigger and keyword options.

    When now is absent, DateTime.now!/2 samples the wall clock using config :bacstack, :default_timezone, falling back to "Etc/UTC" when unconfigured. The timezone database defaults to Calendar.get_time_zone_database/0 and can be overridden through the timezone_database field. Regional zones need a configured database that supports them.

    An omitted monotonic_time is sampled through System.monotonic_time/1 in milliseconds. Explicit clock values are preserved - supplying now bypasses the configured timezone lookup. The options field defaults to []. Runtime state, device identifier and host callbacks default to nil.

    Supply the previous result's state when executing an existing instance. Preparation, execution and nested reads within one operation need to share the same clock samples - create one context for that operation. The constructor's options field contains object-specific options - the outer keyword list configures the context itself.

    Raises ArgumentError for an invalid trigger, unknown field, invalid field value or a timezone that the selected database cannot resolve when sampling now.

    require_operations(context, operations)

    @spec require_operations(t(), [
  :lookup_object | :read_property | :read_property_multiple | :write_property
]) :: :ok | {:error, {:unsupported_operation, atom()}}

    Checks required host operations without invoking callbacks.

    Returns the first absent operation in the supplied order. Requirements belong to the object module and selected configuration: an empty target list, for example, need not require a write callback. Presence alone does not advertise support for remote targets or other optional capabilities.

    write_property(context, reference, value, priority \\ nil)

    @spec write_property(
  t(),
  BACnet.Protocol.DeviceObjectPropertyRef.t(),
  BACnet.Protocol.ApplicationTags.Encoding.t()
  | [BACnet.Protocol.ApplicationTags.Encoding.t()]
  | term(),
  1..16 | nil
) :: :ok | {:error, term()}

    Writes a property through the host callback, or reports the missing operation.

    Priority is nil (omitted) or an explicit slot from 1 to 16. A successful write returns :ok. The value is forwarded unchanged, including a BACnet.Protocol.ApplicationTags.Encoding or list of encodings. The host needs to decode encodings for local writes or forward them to a remote write service, and retain updates to local target objects.
